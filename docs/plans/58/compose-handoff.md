# Hand-off: changes the compose repository needs for plan 58

> Historical record once merged: read it only to understand why a change was made. It belongs to [plan 58](plan.md) of knowledge-hub and becomes its own plan in `andras-tkcs/tkcs-work-compose`. Nothing here is built yet, and this plan edits nothing in that repository. Facts below were read at tkcs-work-compose commit `7fc2c6b`; check each file name before you plan the change.

## What the hub needs from the stack

Every new switch defaults to off, so converging with these changes and the new hub image configures nothing until the variables are set. The hub image is released first (`kh migrate` adds migration `0006`).

| Area | Change in the compose repository |
|---|---|
| New service | `roles/knowledge_hub` (compose template): a second service `knowledge-hub-directory`, the same image, `command: ["directory", "sync", "--every", "300"]`, networks `db` and a new non-internal network `egress`, `read_only`, `cap_drop: [ALL]`, secret `pg_kh_indexer`, `KH_CONFIG_FILE` mount, and only the secrets of the chosen provider. Restart `unless-stopped`. It is the only container that holds a directory credential. |
| Egress | A new docker network `egress` (not `internal`) used only by `knowledge-hub-directory` (outbound to `oauth2.googleapis.com`, `admin.googleapis.com`, or the Keycloak host) and by `knowledge-hub` itself for the sign-in (outbound to `accounts.google.com` and its JWKS host, or the Keycloak host). Prefer an egress proxy or firewall rule that allows only those names. With Keycloak as the upstream, `id.<domain>` resolves through `host-gateway` as PrivacyFence's container already does (`roles/privacyfence/templates/override.yaml.j2`). |
| Public ingress | A public name for the hub (a new entry in `hostnames` in `group_vars/all/main.yml`, for example `kh.<domain>`) through nginx and Cloudflare. Only these paths are public: `/mcp`, `/authorize`, `/token`, `/register`, `/revoke`, `/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource/mcp`, `/oauth/callback`, `/oauth/consent`. They must bypass the Cloudflare Access client certificate the way `n8n_public_paths` does, because claude.ai calls them from Anthropic's servers. `/webhooks/forgejo`, `/metrics` and `/healthz` stay internal. Rate-limit `/register` and `/token` at nginx too. Terminate TLS with a valid certificate. |
| Hub settings | `KH_PUBLIC_URL: https://<hub name>`, `KH_ALLOWED_HOSTS` extended with that host (the hub refuses other `Host` headers), `KH_OIDC_ISSUER`, `KH_OIDC_CLIENT_ID`, `KH_OIDC_CLIENT_SECRET_FILE`, `KH_OIDC_ALLOWED_DOMAINS` (`pf_allowed_domains` plus `keycloak_local_domain` for the test realm), `KH_OIDC_HOSTED_DOMAIN` (the Workspace domain, production only), `KH_ENV: prod`. The `KH_PF_*` variables stay as they are until PrivacyFence retires `audiences_tool`. |
| Rendered `kh.yaml` | `roles/knowledge_hub` renders `directory: {provider: <kh_directory_provider>, domains: <kh_keycloak_domains>, refresh_seconds, max_stale_seconds}` and, per group, `directory.google` and `directory.keycloak` references built from `kh_groups` (for group `all`: Google `kh-all@<domain>` and `kh-all-approvers@<domain>`, Keycloak `kh-all` and `kh-all-approvers`, the names `kh_keycloak_group_prefix` and `kh_keycloak_approvers_suffix` already give). `kh_groups` no longer carries members read from Keycloak. A new variable `kh_directory_provider: keycloak` (default, today's behaviour through the hub) or `google`. |
| `kh_directory` role | Rewrite `roles/kh_directory`: drop the Keycloak admin-API reads (`tasks/main.yml`) and the Jinja skip rules (`tasks/derive.yml`); the hub now applies them (`kh directory people --json`). The role runs `docker exec knowledge-hub-directory kh directory sync --once` (fails the converge on a provider error), then `docker exec knowledge-hub kh directory people --json` and builds `kh_people` (login to email) for `forgejo_kh` from the output; it prints the hub's skip lines. Static `kh_people` and `kh_groups.<g>.members` stay merged by the hub (break-glass). `kh_people_source` values become `hub` and `static`. `tests/kh-directory.yml` and `tests/syntax/kh_directory.yml` change with it. |
| Forgejo accounts | `roles/forgejo_kh` keeps creating one account per entry of `kh_people`. A person added to a Google group appears in `kh directory people` after the next sync; the next converge creates the account and `kh setup apply` adds them to the teams. Until then `kh setup plan` prints an `i account <login>: no Forgejo account yet` line, which does not fail `kh-daily`. Forgejo sign-in still goes through PrivacyFence's OIDC; before PrivacyFence is retired the Forgejo auth source needs its own change (Keycloak or Google directly), which is not part of this plan. |
| Keycloak realm | `roles/keycloak_realm`: add the confidential client `kh-hub` (standard flow, PKCE `S256`, redirect `https://<hub name>/oauth/callback`, scopes `openid email`) and the service-account client `kh-directory` (client credentials; `realm-management` roles `view-users` and `query-groups`); keep the groups `kh-<group>` and `kh-<group>-approvers` and `kh_keycloak_seed`. No `groups` claim mapper is needed. Both secrets are generated into `{{ secrets_root }}` like `keycloak_pf_client_secret` (owner `10001`). For the Google production setup nothing in Keycloak is used by the hub. |
| Secrets | `group_vars/all/main.yml` secret list: `kh_oidc_client_secret`, `kh_directory_keycloak_secret` (generated); `kh_directory_google_key` (the service account JSON, put in the vault, written 0400 to `{{ secrets_root }}`). Add them to the compose `secrets:` of the right service only. |
| Admin tool and `kc-people` | `roles/admin` (`api_kh.py`, `keycloak.py`) and `scripts/kc-people.py` keep working for the Keycloak provider (they edit the `kh-*` groups the hub reads). With the Google provider the people tab must say that membership is managed in Google. `roles/kh_apply` runs `kh-admin` edits of `kh.yaml`; its person and member commands only touch static entries, so the tool should show directory members as read-only. |
| PrivacyFence | No change now. Its declaration, `audiences_tool`, the n8n tokens and the Forgejo OIDC client stay. When the PrivacyFence follow-up retires `audiences_tool`, set `legacy_privacyfence: false` in the rendered `kh.yaml` and drop the `KH_PF_*` variables and `pf-kh` from the hub. |
| n8n | Per workflow: `kh key create` in the one-off container, store the key as a header credential, switch the MCP client node, then revoke the PrivacyFence token. `docs/knowledge-hub.md` "n8n tokens" is replaced by this. n8n is pinned at 2.48.5; its MCP client must support streamable HTTP (unconfirmed, plan manual step ma6). |
| Backups and monitoring | The snapshot and OAuth tables are in the existing `kh.dump`; no change. Alert on `kh_directory_snapshot_age_seconds` above `2 * refresh_seconds` and on `systemctl is-failed kh-daily` (a stale snapshot makes `kh setup plan` fail). |
| Tests and docs | `tests/fake-vars.yml` and the render tests for the new variables and the second service; `tests/render.d/` for the public paths and the two secrets; `docs/knowledge-hub.md` sections "People from Keycloak", "Joiners and leavers" and "n8n tokens"; `docs/keycloak.md` for the two clients. |

## Order of rollout

1. Release the hub; bump and pin the image; converge with nothing set (no change).
2. Create the Keycloak clients (test realm) and the secrets; start the sync service with `kh_directory_provider: keycloak`; compare `kh directory people --json` with the people the old role produced; then switch `kh_directory` to the new behaviour.
3. Public ingress and `KH_PUBLIC_URL`; test claude.ai and Claude Code against the Keycloak sign-in.
4. Create the Google client, service account, delegation and groups (plan manual steps ma2 to ma4); switch `kh_directory_provider: google` and `KH_OIDC_ISSUER`; repeat the checks.
5. Move n8n workflows to hub keys; remove the PrivacyFence connector from Claude clients.
6. Rollback at any step: `kh_directory_provider: none` (static people), unset `KH_PUBLIC_URL` and `KH_OIDC_*` (OAuth off, the PrivacyFence path unchanged), put the old n8n token back until it is revoked.
